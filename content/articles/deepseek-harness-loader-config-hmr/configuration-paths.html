02 / 顺序与等待点

  1. 01
    提交新配置配置树 → Entry

    Entry 接收 fixed: B，并保留新的原始 options。

    保存新原始值原始配置 → Loader

    Entry 与 Fiber 保留新的原始配置，以供后续激活使用。

    保留新原始输入新输入 → Entry

    Entry.options.config 与 Fiber._config 已保留 live: 42。

    备份并清理缓存HMR 队列 → 模块缓存

    选定受影响模块；保存旧 Fiber、entry 与当前原始配置。

  2. 02
    解析并更新Entry → Fiber

    候选配置通过钩子与 schema 后，进入 internal/update。

    比较原始改动Loader → 候选与引用

    只有 config 变化、Fiber ACTIVE、父 Context 未变，才考虑快速路径。

    进入候选解析Entry → 校验与日志

    原始改动符合快速路径条件，开始解析并验证候选。

    重新导入入口模块缓存 → HMR 队列

    所有替换入口先导入；此时尚未删除旧 runtime。

  3. 03
    开始释放资源Fiber → 插件资源

    默认 restart 先发起卸载，已登记资源进入清理。

    解析并验证候选Loader → 候选与引用

    执行真实 internal/config 与 schema，得到新的候选运行配置。

    候选验证失败校验与日志 → Entry

    字符串字段收到数字，验证抛出错误，进入 catch 分支。

    删除旧 runtimeHMR 队列 → 旧实例

    等待保存下来的旧 Fiber 完成清理。

  4. 04
    等待旧资源退出插件资源 → Fiber

    异步清理完成后，才继续本轮装载。

    检查普通有效值候选与引用 → Loader

    普通有效值必须保持相同；否则回到普通更新。

    记录校验警告Entry → 校验与日志

    Loader 记录失败；原始输入不会在这里自动还原。

    创建替换实例HMR 队列 → 新实例

    按原命名空间选择实现，恢复对应 entry 关联。

  5. 05
    按新配置 applyFiber → 插件资源

    插件再次执行，按 fixed: B 登记新的资源。

    提交全部快照Loader → 候选与引用

    live 与 count 的引用身份保持不变，当前值一起更新。

    跳过快照提交Entry → 运行引用

    候选没有提交，运行引用依然返回 one。

    等待新实例稳定新实例 → HMR 队列

    等待新 Fiber 与 Loader；稳定并不一律等于 ACTIVE。

  6. 06
    生命周期稳定插件资源 → Fiber

    Fiber 对象与 uid 保持不变，实验轨迹以新 apply 完成为终点。

    通知 ownerLoader → owner Fiber

    事件带有字段路径；通知前所有引用已提交，其他实例不接收。

    确认运行状态运行引用 → Entry

    实验终点：Fiber 仍 ACTIVE，没有 volatile 更新事件。

    提交命名空间记录HMR 队列 → 模块缓存

    成功后更新 entry.moduleNamespace，再发 hmr/reload。
