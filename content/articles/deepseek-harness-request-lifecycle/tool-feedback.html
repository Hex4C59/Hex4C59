模型给出调用意图

assistant/message 已记录 read 调用。c1 是这次调用的标识；文件内容还没有返回。

先留下调用记录

调度器先追加 tool/call，并保留它的事件序号。后续结果将引用这个序号。

运行时接手执行

工具运行时按 prepare、策略检查、执行与结果处理的路径调用 read。图中只展开正常读取路径。

返回值成为会话事件

tool/result 携带工具消息，并用 sourceEventSeqs 引用先前的 tool/call。Session 先提交到内存记录。

下一 Step 读取会话表面

正常继续路径进入下一 Step。prepareRequest() 调用 session.deriveMessages()，得到包含工具结果的消息历史。

冻结请求，再交给模型

边界消息和请求被冻结，随后交给 adapter.stream()。模型这次获得了 read 的返回内容。

模型 · 产生调用意图

assistant/message 结算后提取工具调用。模型提供名称、调用 ID 与参数；文件读取由工具运行时执行。

Agent · 组织下一 Step

executeToolCalls() 调度本轮工具；正常继续时，prepareRequest() 派生并冻结下一轮消息。

工具 · 返回执行结果

调度受执行模式与屏障约束。commitReady() 按模型调用顺序提交结果，完成顺序可以不同。

Session · 保存事件并派生表面

tool/result 引用 tool/call 的序号；deriveMessages() 将会话表面投影为消息历史。提交与刷盘分开。
