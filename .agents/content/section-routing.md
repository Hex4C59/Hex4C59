# 文章栏目归类规则

适用于新建文章、规划或续写系列，以及调整已发布文章的栏目。写作前先确定文章来源和读者的主要阅读目的，再选择正文存放目录。栏目判断以本文件为准；选定栏目后，再读取相应的模板和写作规则。

## 判断顺序

按以下顺序判断，命中后确定一个主栏目：

1. 正文主要是翻译，或沿着某篇外文原作忠实转述，归入“译文”。引用外部资料后独立组织、比较和论证的文章，继续按后面的规则判断。
2. 原创文章主要讨论 AI Agent 的机制、设计、实现、评测或工程实践，归入“Agent”。该专题中的基础知识讲解、实战教程和工程经验都放在这里。
3. 其他原创文章以教会读者一个知识点或一项操作为主要目的，归入“教程”。包括语言语法与原理、工具操作、项目实践和配套参考。
4. 主要分享个人经历、实践记录、产品比较、选型判断、观点或生活思考的文章，归入“随笔”。

判断前用一句话写清文章的目标，例如“读者读完能解释 Rust 借用规则”或“读者能了解我为什么选择这个模型”。这句话可以放在写作计划里，正文开头按技术写作规范表达，无需增加 front matter 字段。

多个条件看起来都适用时，先执行来源和 Agent 专题的优先规则，再按文章的主要目标区分教程与随笔。不要只凭标题中的“指南”“入门”“实战”，或正文是否出现代码决定栏目。

## 栏目范围与存放目录

| 栏目 | 正文目录 | 收录范围与边界 |
| --- | --- | --- |
| Agent | `content/agent/<slug>/index.md` | Agent 的概念、系统设计、工具调用、记忆、规划、协作、评测与工程实践。教程形式的 Agent 文章也在这里。只是在模型比较或产品体验中提到 Agent，继续按文章的主要目标归类。 |
| 教程 | `content/tutorials/<slug>/index.md` | 面向学习或操作的知识讲解、操作指南、项目实践及配套参考。可以是单篇，也可以是连续课程；原理讲解无需硬写成操作步骤。 |
| 随笔 | `content/posts/<slug>/index.md` | 经历与观察、个案记录、工具或产品的比较与选型、个人观点和生活内容。技术文章也可以是随笔，但必须符合这些目的。不能因为尚未判断栏目就默认放进 `posts`。 |
| 译文 | `content/translations/<slug>/index.md` | 以外文原作为主体的中文翻译或忠实译述，保留原文来源、作者和必要的翻译说明。即使主题是 Agent 或 Rust，也优先放在这里。 |

Agent 专题可以收录学习路线所需的前置知识，例如作为 Agent 工程系列基础篇的检索增强生成（RAG）讲解。与 Agent 学习路线无关的通用数据库、检索或编程教学，按“教程”归类。不能仅添加一个 Agent 标签或系列字段，就把无关文章放进 Agent 栏目。

“教程”与“随笔”的区别在于文章提供什么：解释可复用的概念、规则或操作方法，按教程组织；记录一次经历、比较产品并给出个人判断，按随笔组织。从个案中整理出的通用教程，需要补齐读者所需的前提、解释或操作依据，才能按教程发布。

写 Agent 文章时使用 [Agent 专栏规范](agent-section.md)和 [Agent 模板](../../archetypes/agent.md)。译文使用 [译文模板](../../archetypes/translations.md)，教程使用 [教程模板](../../archetypes/tutorials.md)；其他文章遵循[通用技术写作规范](technical-writing.md)及现有 front matter 约定。

## 容易混淆的例子

以下例子同时包含现有文章和假设题目，用来说明归类边界。

| 内容 | 主栏目 | 判断理由 |
| --- | --- | --- |
| Rust 从零开始、所有权与生命周期讲解、课程练习和排错附录 | 教程 | 目标是学习 Rust，原理讲解和配套练习都属于课程内容。 |
| 用 Rust 实现 Agent 的工具调度与权限控制 | Agent | 主旨是 Agent 的运行机制；Rust 是实现语言。 |
| 从零构建 CLI Coding Agent | Agent | 虽然是实战教程，核心主题仍属于 Agent 专题。 |
| DeepSeek Harness 的请求生命周期与系统架构分析 | Agent | 分析 Agent 系统的实际设计与实现。 |
| Agentic Engineering Patterns 的中文翻译 | 译文 | 外文原作是正文主体，来源规则优先。 |
| 阅读 Rust 官方文档后，独立组织的借用规则讲解 | 教程 | 引用官方资料后独立讲解知识，并非沿原文翻译。 |
| 主流大语言模型的产品比较与选型建议 | 随笔 | 主要提供比较与选择判断，提及 Agent 使用场景不会改变主旨。 |
| 从安装 Hugo 到部署个人博客的完整方法 | 教程 | 提供读者可以照着完成的通用操作方法。 |
| 这次博客迁移的经过、遇到的问题与个人取舍 | 随笔 | 主要记录一次具体经历；有命令或代码也不自动成为教程。 |

## 栏目、系列与标签分别负责什么

每篇正文只存放在一个主栏目中。主栏目由正文所在的内容目录决定；已经发布的旧网址可以通过 `url` 字段保留，网址前缀不作为归类依据。

“系列”用于组织相关文章和阅读顺序。正文仍放在 Agent、教程、随笔或译文中；`content/series/<key>/_index.md` 用于系列说明和阅读入口。系列目录页不是另一个正文存放栏目。

- 连续课程的原创正文、课程目录、练习和排错资料使用同一个主栏目。Rust 教材及其附录统一放在“教程”；Agent 专题课程统一放在“Agent”。
- 正式章节通过 `series` 和阅读顺序字段加入系列。独立附录可以只由课程目录链接，不计入正式章数。
- 跨栏目专题合集可以用同一系列组织原创与译文；每篇文章仍按来源和主旨归类。
- `tags`、`categories` 用于主题检索；`article_type` 等字段用于栏目内的文章类型。它们不替代主栏目，也不要求重复存放正文。例如 Agent 文章的 `article_type = "tutorial"` 表示文章形式，正文仍在 `content/agent/`。

规划新系列时，先写明受众、主要目标、主栏目和成员范围，再编排章节。续写前核对已有规划及这些规则；发现旧目录与主旨不符时，说明应如何归类，按下节要求处理已经发布的文章。

## 调整栏目与新增栏目

调整已发布文章的栏目时，迁移整个文章目录，连同图片、图表和下载资源一起保留。默认使用 `url` 保留原地址。例如 Rust 所有权文章的源文件已在 `content/tutorials/rust-04-ownership/index.md`，但 front matter 保留：

```toml
url = "/posts/rust-04-ownership/"
```

检查导航选中项、面包屑、栏目列表、系列入口、搜索、归档、订阅源和评论配置是否符合新的主栏目，同时确认旧文章地址、图片和下载地址仍能访问。文章的历史网址中保留 `posts`，不表示它仍属于“随笔”。

系列的 `series_start` 由当前模板通过 `site.GetPage` 查找内容页，迁移后应填写新的内容路径。例如 Rust 学习指南填写 `/tutorials/rust-00-learning-guide/`，正文中的公开链接仍可使用保留的 `/posts/rust-00-learning-guide/`。

已有栏目都无法合理容纳内容时，先说明它与这些栏目边界的差别，并提出栏目调整方案。新增栏目应有持续的内容计划或明确的长期用途，再同步维护本规范、栏目入口和站点集成；单篇文章有多个标签不构成新增栏目的理由。

## 完成检查

新建、续写或调整归属后，逐项确认：

- 文章来源和主要阅读目标对应上述判断顺序，正文目录符合选定主栏目。
- 系列、标签和文章类型准确表达内容，没有用这些字段代替栏目归类。
- 课程正文与配套资料的归属一致，正式章数与附录的处理符合系列规划。
- 已发布文章的旧网址和资源地址得到保留；需要改变网址的任务另行处理跳转、资源链接与评论关联。
- 涉及站点行为的变更按 [Hugo 发布规范](../hugo-publishing.md)检查生成页面；内部规则文档修改检查引用路径和 `git diff --check`。

内容含糊时先核对开头、主要章节和结尾承诺给读者的结果。若仍无法确定主要目标，说明歧义和建议归属后再向用户澄清；不要把“随笔”当作未分类文章的默认去处。

## 配置与自动检查

栏目名称、导航顺序、文章收录和评论开关集中在 `data/sections.toml`。Agent 的文章类型值与显示标签集中在 `data/article_types.toml`。添加栏目或类型时先更新这些文件，再同步对应模板和本规则中的语义边界。

发布检查会拦截未知栏目、无效字段、重复的系列排序、错误的系列入口、站内失效链接和锚点。程序不能根据正文判断文章的主要目的；“为什么归在这个栏目”仍按本文件的判断顺序人工确认。构建、检查和课程打包命令见[维护说明](../../docs/development.md)。
